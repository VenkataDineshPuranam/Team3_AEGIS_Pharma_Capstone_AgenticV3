AEGIS V3 Blueprint

A governed, observable, multi-agent decision-support system for six pharmaceutical workflows. Six LangGraph graphs from one template, two LLM calls per run, nine deterministic control nodes, and no path by which generated text reaches a caller without passing a guard, a critic, the guard again, and a named human.

This page states the frame the system was built to answer, the nine decisions that shaped it, the agentic design those decisions produced, and a map of the whole running application end to end.

The whole application, end to end

Seven layers, forty-seven components. Read it downward: a request enters from the browser, crosses the API boundary, runs the governed pipeline, reaches tools, and only then touches an external system. Governance artifacts and the delivery pipeline sit underneath because they constrain everything above them rather than participating in a request.

SCQA — the frame, as finalized

Narrative class decision-ready. The Answer is capability-level by design: it deliberately does not pick the agent count, the graph shape, or the tool names, because those are downstream decisions that the governance and cost work had to shape first.

Situation

The predecessor is a complete, evidence-grounded capstone: 84 injects across 13 dimensions, 143 datasets, 32 knowledge and policy documents, and a 30-artefact rubric, built around governed pharma decision-support workflows.

Its pattern is single-shot — one governed request in, one JSON-contracted response out, graded by a deterministic harness. Well-governed and thoroughly evidenced, but it exercises no multi-step reasoning, no tool use, no inter-agent handoff, no caching and no runtime observability. It never needed to.

Complication

This system must become agentic while performing the same workflows under the same non-negotiables — synthetic data only, full evidence provenance, and no agent making a terminal safety decision. That is a compound problem on six axes at once:

Technical — orchestration, tool contracts and shared state did not exist. Governance — the hardest constraint is more fragile in a multi-agent design, because authority can leak across a handoff in a way a single-shot app structurally cannot exhibit. Cost — multi-agent designs multiply model calls per request. Caching — a cache hit can silently serve an answer based on since-superseded evidence. Compliance — EU AI Act and ISO 42001 obligations the predecessor never carried. Infrastructure — a hosted tracing service versus a previously offline framing.

Question

How should this system be re-architected as a governed, observable, multi-agent system that preserves domain correctness and the prohibited-decision boundary while adding orchestration, tool use, caching and observability — without inventing an architecture before the domain, governance and cost constraints that must shape it are established?

Answer

Proceed as an additive re-architecture, not a domain rewrite. Carry the domain model, constraints and evaluation floor forward unchanged as the substrate, and layer governed multi-agent capability on top — sequencing the work so governance and authority boundaries, then cost and architecture constraints, are settled before any topology or tool contract is locked, and before any application code is written.

Building the app last is not incidental process. It is the risk-reduction strategy, and it is how this programme avoided the standard failure mode of agentic rebuilds: designing the graph before the domain.

Nine decisions, all accepted

No ADR rests on an unconfirmed assumption and none carries an open sub-decision. Both evidence-acquisition blockers closed: the air-gap question was settled by sponsor decision, and the accountable-approver question by taking roles verbatim from the stakeholder pack.

ADR-001 · FACT — SPONSOR DIRECTIVE

Runtime stack: LangGraph, LangSmith, Redis

LangGraph for stateful orchestration, checkpointing and human-in-the-loop interrupts; LangSmith for tracing and evals; Redis for the response cache.

Direction-setting rather than waste-resolving, and flagged as such rather than retrofitted with a rationale.

ADR-002 · FACT + VERIFIED CONSTRAINTS

Built as an independent codebase

The predecessor is a read-only evidence and reference source — cited for domain facts, never imported as code.

Produced a standing working rule: verify a claim against the actual source, never against a filename or a prior summary.

ADR-003 · FACT — VERIFIED AGAINST GRADER CODE

Evidence authority is a deterministic gate

Authority is a status lookup, never a model judgement. Both untrusted and superseded are non-citable, filtered at the retrieval boundary so they never enter a context window. Retrieved content may never alter its own authority — embedded instructions are data, never directives.

This ADR corrected the domain model, which had said superseded documents should be "flagged, not silently substituted." Reading the real grader showed both statuses are hard exclusions.

ADR-004 · FACT + DERIVATION

Prohibited actions are structurally unrepresentable

Three independent layers, none of them a prompt instruction: the aggregate schema has no disposition field; no tool exposes a write or disposition method; and a runtime guard checks every candidate output.

"Runtime guard only" was explicitly rejected — a guard is a single point of failure. The guard is the third layer, not the control.

ADR-005 · DERIVATION

Governance is a separate container

The policy engine deploys separately with an independently versioned policy contract. Unreachable means the request is refused — no cached-policy fallback, no warning-and-continue.

Deliberately not a shared kernel, so policy cannot be quietly weakened by a core context's local convenience.

ADR-006 · DERIVATION + FACT

Audit records live in an owned store

Compliance AgentRun records go to a store this system owns. Tracing stays in LangSmith and is additive, never load-bearing for compliance or for request success.

The alternative couples a regulatory retention obligation to a third party's SLA and retention policy.

ADR-007 · FACT — EAB-2 CLOSED

Degraded-mode-safe, not offline-capable

Every hosted dependency has a documented fallback that preserves correctness while sacrificing capability. Model unreachable ⇒ abstain, never guess. Tracing unreachable ⇒ log locally, never block. Cache unreachable ⇒ no-cache, never serve stale as-if-fresh. Tool server unreachable ⇒ abstain and escalate.

A real departure from an inherited non-negotiable, ratified by the sponsor rather than quietly dropped. The air-gapped variant is recorded as a known limitation.

ADR-008 · DERIVATION

One deployment, one graph per workflow

Each workflow gets its own graph with its own domain agent, critic and HITL interrupt. No graph may invoke another graph's agent. Shared capability is reached as a service, never as an agent-to-agent call.

Accepted while the cost baseline was still Unknown — recorded as residual risk RR-1 with a trigger that reopens it if the first real measurement lands badly.

ADR-009 · FACT — ROUTE A CONFIRMED

Azure is the target platform

Container Apps for compute, Azure Cache for Redis, Blob Storage with WORM immutability for audit, Key Vault for secrets, Entra ID for identity. Inference runs Route A — the model hosted behind Azure AI Foundry rather than called directly.

The ADR predicted that binding to Foundry would be "a config/client change behind one interface, never a model or prompt-behavior change." Implementing it touched one file and changed no prompt and no parser — the prediction held.

Two consequences that improved earlier decisions. Entra ID turns the named approver roles into real group assignments, so "authorization checked at execution time" becomes a platform property rather than an aspiration. And keeping OpenTelemetry as the instrumentation layer leaves the trace backend swappable, which is what keeps ADR-006's independence from a vendor honest.

Agentic architecture

Four agents in the whole system. An agent node is one whose output depends on a model call; everything else is deterministic. That distinction is load-bearing — only agent nodes can produce unbounded text, so only agent nodes need an authority limit and a stop condition. Deterministic nodes have contracts, not authority.

Three more (research_review, clinical_integrity, regulatory_completeness) were added later, and their graph code (services/api/research_graph.py and siblings) instantiates the identical twelve-node template confirmed in the section below — same guard-critic-guard shape, same node names. But the roster document itself was never extended with a named, authority-scoped entry for those three domain agents. Router–executor–critic, deliberately not planner–executor–critic

Why there is no planner agent

  • There is nothing to plan. Each workflow's sequence is fixed and written down. The variability is in content, not in order — a planner would be a model re-deriving a constant.
  • A planner is a new authority surface. An agent that chooses which tools to call, in what order, can in principle choose an order that skips a gate. Deterministic routing makes that unrepresentable rather than unlikely.
  • It is pure token waste — an extra call plus state re-serialization on every run, for a plan that never changes.

The cost of that choice, stated

  • The graph is less adaptive. A genuinely novel request shape cannot be handled by re-planning.
  • It hits abstain and a human instead.
  • For a decision-support system whose safe default is abstention, that is the correct failure direction — but it does mean the system abstains on cases a more autonomous design might have handled.

Critic scope — complementary to the deterministic gates, never overlapping

A critic re-checking what a schema already enforces is designed-in token waste on every run. The rule: if a check can be expressed as a lookup, a type, or a pattern match, the Critic does not perform it. The Critic exists only for checks that require reading the argument.

Cross-workflow reuse — shared as a template, never at runtime

Governed spine

Shared as a template. Identical structure, instantiated six times.

Prohibited-action guard

Shared code, per-workflow prohibition contract injected. One workflow's list must never load into another's graph.

Critic / Verifier

Shared implementation, one instance per graph. Reasons only over the common output contract, so it needs no workflow vocabulary.

Domain agent nodes

Not shared. One per context — a generalist agent was explicitly rejected at the domain-design stage.

Retry legitimacy — a closed enum, not a counter

A retry is only legitimate if it carries a diagnosis. The Critic must return a reason code from a closed set, and that code must differ from every prior code in the run. One code has no retry edge at all.

MISSING_CITATION

A claim carries no citation.

CITATION_UNRESOLVED

A citation points at nothing in state.

CLAIM_EXCEEDS_EVIDENCE

The claim says more than the source does.

ABSTENTION_EXPECTED

Evidence was thin; the draft answered anyway.

CONTRACT_VIOLATION

Output does not conform to the schema.

PROHIBITION_ADJACENT

No retry edge exists. Checked first, unconditionally, before any other routing.

The governed spine

Twelve nodes. Two of them call a model; nine are deterministic; the rest are terminal. That ratio is the design — every control in this system is deterministic, and no control is implemented by a model.

Read the graph for what it refuses to do. The absent edges carry more of the design than the present ones. Synthesis is unreachable without sufficient, citable evidence; a draft is unreachable by a human without two guard passes and a critic; and a response is unreachable by a caller without an audit write.

What is deliberately absent

No write path to any system of record

Eight tool contracts, zero write methods. The tool manifest declares this and the AI-BOM hashes the manifest, so weakening it fails the build and refuses the container start.

No cross-run agent memory

A deliberate omission, which is why context-poisoning across runs is marked not-applicable rather than mitigated. Reversing it would reopen that threat.

No planner, and no cross-graph call

Routing is a pure function of state. A run holds a credential for its own bounded-context tool server and no other.

No control implemented by a model

Every hook binding would behave identically if the system prompt were deleted entirely — which is the actual test of "not prompt-dependent," and a stronger claim than "the design intends this."
